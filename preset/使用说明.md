# 白描回廊 v1.0 · 使用说明

一套 SillyTavern 的**对话补全（Chat Completion）生成预设**。不绑任何角色卡，也不绑任何模型渠道——装在哪个卡上都能用。

---

## 一、它是什么

预设 = 一组「塞进 AI 提示词里的规则条目」+ 一组采样参数。

装上之后，AI 每次生成时，会先读到这套规则，再开始写。它管七件事：

| 管什么 | 你去哪一节改 |
|---|---|
| 写成什么样（文风） | 🖋️ 文风（选一） |
| 写多少字 | 🖌️ 正文字数（选一） |
| 谁来写、谁的脑子能看 | 🥷 人称与视角（选一） |
| 能不能替你说台词、替你行动 | 🔫 抢话与角色自主性 |
| 剧情推多快、多狠、多露骨 | ⏩ 推进速度 / 🔥 烈度 / 🔞 情色尺度 |
| 回复尾巴上挂什么（摘要条、变量块） | 📋 输出格式 |
| 模型不听话时怎么掰回来 | ----🚫🔓 破甲 ---- |

---

## 二、已经帮你装好了

预设已通过酒馆官方接口写进你的宿主：

```
F:\sillytavern\SillyTavern\data\default-user\OpenAI Settings\白描回廊 v1.0.json
```

打开酒馆 → 右上角「插头」图标（AI Response Configuration）→ 最上面「Chat Completion」那一栏的预设下拉框 → 选「白描回廊 v1.0」。

> 如果下拉框里没有：按一下浏览器 F5 刷新页面。

**要换到别的电脑／给别人用**：直接发 `白描回廊 v1.0.json` 这个文件，对方在同一个下拉框里点「导入」即可。

## 三、默认开着什么

一共 66 条条目，其中 40 条默认开启。**你什么都不用动，直接就能跑。**

默认开的（按生效顺序）：

- 主线三条内置：Main Prompt（写作总纲）／Auxiliary Prompt（成人内容许可）／Post-History Instructions（输出纪律）
- 🖋️ 文风·文学向白描
- ✔️ 反八股总则
- ⛔ 禁词·通用
- 🥷 第三人称限知
- 🔫 抢话·正常 ＋ 🧍 角色自主性
- ⏩ 稳步推进 ＋ 🔥 标准烈度 ＋ 🔞 直白
- 🖌️ 800–1500 字
- 🎚️ 小说正文
- 📋 折叠摘要条 ＋ 🔒 状态/变量块保护 ＋ 🚫 防截断 ＋ ⚡ 规则冲突优先级
- 14 条分区标题（空条目，只是分隔线，不占 token）

默认关的（想用再开）：冷硬镜头／网文爽感／对话驱动、两个文风碎片、DeepSeek 禁词、Gemini-Claude 禁词、自定义禁词模板、第二人称／第一人称、两个更严的抢话档、慢炖／快进、高烈度／黑暗向、含蓄／浓烈、其他三档字数、对话速写、严格破限、预填充破限、思考段处理。

## 四、最常调的六件事

全部在酒馆的「提示词管理器」里操作：预设下拉框右边那个**滑块图标**打开。

规则很简单：**每个分区只能开一条**（分区名里写着「选一」的），把它们当成互斥的单选题。

### 1. 换文风
🖋️ 分区里四个选一个：文学向白描（默认）／冷硬镜头／网文爽感／对话驱动。
下面的「附加文风碎片」可以另外叠加（可多开）。

### 2. 换字数
🖌️ 分区四选一：400–800／800–1500（默认）／1500–3000／不限。

### 3. 换人称
🥷 分区三选一：第三人称限知（默认）／第二人称／第一人称限知。

### 4. 破甲加码
`----🚫🔓 破甲 ----` 分区里有两档，默认都关：

- **普通档**：不用开，它已经常驻在主线三条内置条目里了。
- **🔓 破限·严格（英文长块）**：模型明显开始回避、打码、说教、绕开暴力或情色时开它。开了通常就够。
- **🔓 破限·预填充抢跑**：上面那档还不够时再开。它是在对话最末尾插一句 assistant 的话，逼模型顺着往下写。**各渠道的思考结束标记不一样**，条目开头有注释说明怎么改；开着不管用就试试在正文开头加你那个渠道的 `<｜end▁of▁thinking｜>` 之类的标记。

### 5. 禁词按模型开
⛔ 分区：通用那条默认开，够用。如果你用 DeepSeek 系或 Gemini/Claude 系，把它们各自那条也打开（这些模型的固定口癖不一样）。
想禁自己的词：打开「✏️ 禁词·自定义」，把里面的示例改成你要禁的词。

### 6. 关掉摘要条
**如果角色卡自带状态栏或自己的摘要格式，把 📋 折叠摘要条关掉**，否则会双方各输出一份。
（这条的注释里也写了这句话，打开就能看见。）

## 五、摘要条长什么样

默认开着，每轮回复正文结束后会挂一个可折叠的小尾巴：

```
<details><summary>摘要</summary>

时间：18:20 → 18:35
地点：学院中庭 → 地下回廊
BGM：luminous
伏笔：
- 短期[2/5] 中庭那座停摆的钟
- 长期 教习提到过的「第九次」

</details>
```

只记四样：**时间跳转、地点移动、BGM、伏笔/未解事件**。

两条设计上的硬规则：

1. **摘要永远排在变量块前面。** 你那张卡的「三楼前变量隐藏」正则会把旧楼层的 `<UpdateVariable>…</UpdateVariable>` 整段删掉；如果摘要写在它后面，会被一起误删。
2. **摘要里不许出现 `【名字】：『台词』` 这种形状。** 你卡的「对话美化」正则会把这种形状认成对话，套成气泡。

没有 BGM 系统的卡，「BGM」那行写「无」，不会乱报曲名。

## 六、和角色卡自带变量系统的关系

预设**不改**任何卡的变量规则，只做一件事：**提醒模型别把格式写坏**。

「🔒 状态/变量块保护」那条的内容是：标签名、字段名、层级、数组包裹方式照抄；不许省略、合并、缩写、自创字段；整块放最末尾；找不到规定格式就不输出。

字段含义、取值范围、更新规则——全部以角色卡和世界书为准。预设一个字都没有改。

所以这张卡的 MVU 变量、状态栏、前端渲染，全都照旧工作。

## 七、想改文字怎么办

这套预设是**从一份文字源生成的**，不是手改 JSON。改文字请改源文件：

```
preset/preset_content.py    ← 改这里（全部条目正文都在这一个文件里）
```

然后按顺序跑三条命令：

```bash
cd F:/sigil-circuit/preset
python build_preset.py     # 生成 JSON，结果看 _build.log
python check_preset.py     # 结构自检，结果看 _check.log，必须 0 FAIL 0 WARN
python install_to_host.py  # 装进酒馆，结果看 _install.log
```

**别直接改 JSON**——下次一跑 build 就被覆盖了。

自检会查：JSON 能解析、没有会弹敏感字段框的连接类字段、每条自定义条目字段齐全、marker 条目不带正文、prompt_order 有真正生效的 100001 组、选一分区没同时开两条、注释宏配平、正文标签全部配对。
