## 3. 制作链与可替换合同

1. **身份页**：原画路径/指纹、必须保留的特征、不应自行增加的服装/装备/能力。研究姿势可以试，但内容设定不能由生成结果反推。
2. **尺度比较**：同角色同姿势只比较两种以内像素高度；放进相同 UI、场景、1×与目标显示尺寸，记录清晰度和工时。当前 160×160 是画布，人物约 114–122 逻辑像素高；这是草稿数据，尚非正式比例决定。
3. **动作卡**：明确用途、进入/离开状态、地面接触区间、重心路线、起势/发力/随动/收招、是否有意挪步、循环、事件点和中断策略。先画主要姿势，再补轨迹和中间帧。
4. **Aseprite 源**：保留 `.aseprite`、分层、标签、逐帧时长、root 锚点及可编辑关键姿势。生成候选与整理后的源分开留档，失败稿有版本标记，不能覆盖后再说“已经修过”。
5. **清像素与中间帧**：逐帧修解剖、体积、轮廓、明暗和附属动作；不靠整图平移、横向拉伸、自动插值或滤镜来冒充躯干/关节运动。当前局部腿位移修正只是研究补丁，膝部仍需重新审视和重画。
6. **导出**：PNG 图集＋JSON（帧矩形/时长/标签/root），透明边缘不混色；由同一个源导出，禁止单改运行 PNG 后丢失可重建性。
7. **导入**：Godot 以 nearest 采样，整数角色显示倍率，锚点固定；不同帧的时长按毫秒表达，演出时长从元数据取得。UI 字体可使用适当抗锯齿，不能因此让角色像素被整体平滑。
8. **实机回归**：新图只替换资产与对应描述，不改伤害规则、请求 ID 或结果语义。检查暂停、跳过、失焦、重进、窄面板和正式背景下的读形。

当前复现命令：在工程根目录执行 `& .\tools\build_art_study.ps1`。现有 Aseprite GUI 程序的直接调用可能先返回，脚本已改为等待进程结束；脚本退出成功后仍核对产物内容。该脚本从候选重新生成研究源，会覆盖研究源；若开始手工精修，先另存新版本，并将正式精修源从“候选生成脚本”的覆盖目标移出，再写新的导出入口。

## 5. 三层验收：三层分别判定

### A. 文件和结构检查（自动）

当前 `python .\tools\check_art_assets.py` 检查 480×320 图集、6 个 160×160 帧、正时长、最多 25 色、二值透明、边界不裁切、源文件存在。输出 `evidence/art-structure-02.json`。这些固定尺寸只针对该研究稿；将来不同动作应通过各自声明校验，不能把 6 帧写成全项目通用规定。

### B. 引擎与交互检查（实际运行）

| 步骤 | 预期 | 失败判定/处理 |
|---|---|---|
| 主动和剧情各进一次测试战斗 | 同一角色、场景、动作链 | 两条入口显示不同资产或状态，检查任务/表现绑定，不复制两套战斗 |
| 攻击→看完→再次攻击 | 播一次、解锁输入、从正确状态接续 | 永久锁输入/中途跳姿势，修播放器状态后重测 |
| 起势时暂停→继续；失焦→回到游戏 | 角色和演出时钟一起停/继续 | 只停计时但帧继续跑，或规则再提交，拒收 |
| 相同已提交行动分别看完与跳过 | 结果与行动数一致 | 跳过多扣/少扣生命，属于规则/表现耦合缺陷，立即返工 |
| 中途重载 | 已提交行动保留，回到可理解的恢复状态 | 以动画播放帧推算伤害、重新结算，拒收 |
| 1×、目标倍率、窄板块、复杂背景 | 不糊、不切角色、按钮可达、目标读得清 | 先查画布/CSS/引擎缩放，不通过整体高清平滑掩盖问题 |

本轮已证明两入口播放、重载与结果流程；本轮尚未完成动画各相位暂停/跳过、复杂背景、音画事件点、低帧率与窄尺寸的完整新回归。

### C. 自然动作检查（正常速、0.25×、逐帧）

| 维度 | 通过要求 | 明确拒收条件 |
|---|---|---|
| 身份/读形 | 原画关键特征在实机尺寸可认，姿势意图清楚 | 换脸/发长/衣服结构无意跳变，手和身体糊成一团 |
| 起势与发力 | 有适合动作的准备，胯/胸/肩/手有因果顺序，发力段节奏清楚 | 手突然伸出但躯干不参与；只是两张图来回切 |
| 重心与接地 | 支撑脚和身体重量相符；若有意拖步/滑行，动作卡有说明且可读 | 脚钉住而身体无理由漂移；膝盖/脚踝突变；用全图挪动假装迈步 |
| 体积/关节轨迹 | 头、胸、骨盆和四肢体积沿合理透视变化，夸张有连续过渡 | 肢体长短/粗细突然变，关节逆折或一帧瞬移 |
| 发尾/衣摆 | 跟随主体有延迟、有回摆、有收束 | 主体停止，头发瞬间换形；全身同一拍停止像纸片 |
| 随动/收招 | 发力后有余势，回到待机或下一动作无突兀跳切 | 末帧与 idle 不连续，重复动作出现明显卡点 |
| 时长与命中 | 可感知的接触点与受击/声音/数字对应，跳过仍同结果 | 未出手就命中、接触后隔很久才反馈；所有帧等时长导致拖沓 |
| 像素/场景一致 | 轮廓、细节、色阶与本作通过样板一致，角色与背景处于同一视觉尺度 | 角色像素、背景高清、特效模糊；靠缩小截图隐藏瑕疵 |

人工记录必须写：源/图集指纹、构建版本、显示尺寸、看过的速度和动作链、每项 pass/fail/unverified、具体失败帧、证据路径、返工责任/下一动作。不可用均分抵消硬失败。自动化可标结构通过，执行者可标视觉审查结果；**只有用户明确接受才记 `driver-accepted`**。

## 6. 当前不通过项如何继续
