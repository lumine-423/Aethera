# 第八轮玩家流程与机制合同

按原计划P3/P4/P5推进。用户已要求全面转向底座机制；本轮从旧单体调试底座前进到：行动室→任务列表→1–2人编队→出击准备→回合战斗→胜负/撤退结算→战报→再次行动；设置/刷新/保存返回贯穿流程。没有新建商店/经营/探索/内置剧情等尚未采用模块。

规则与画面分开：combat_rules.gd只处理playable-rules-08配置与状态、验证行动/目标/版本、确定性敌方阶段、行动历史重放；game_shell.gd拥有页面/选择/暂停/本地恢复/展示；角色资产未来单独绑定。旧battle_session.gd和host协议01/02留在/probe诊断，原存档不升级。新首页是Godot玩家流程，当前**本地开发演练模式**，尚未接真实角色卡。不得把新玩法结果塞进旧probe结果结构。

gameplay_08.json是可审阅的游戏设计候选，非正式世界书技能/首发阵容或数值。凛零输出/解放/飞星，明空治疗/护盾，叶能量调度/单次伤害增益；支持1–2人，每角色每回合一次行动，之后存活敌方行动；奇数普通/偶数双倍重击，目标按回合在存活队伍顺序间轮换，显示当前预告。若早先敌人使目标倒地，之后敌人重新选存活者，UI预告是当前状态。治疗上限、无倒地复活、护盾上限40、能量上限100、防御一敌方阶段、增益下次伤害消费一次、技能冷却均明确。

指令流程：角色→行动→合法目标→确认；选择/取消不扣资源。提交验证expected revision防重复，状态先结算，再保存；表现不写规则。失焦/恢复暂停。动作历史200条上限以平局结束，避免辅助单人死循环。撤退无正式奖励/永久惩罚。战报按request_id去重最多20条。局内保存只存版本/准备/行动，不接受HP/能量直接注入；恢复在临时实例重放，失败不替换当前状态。终局与写战报之间刷新可从终局检查点恢复同结果。

本地保存是user://playable_08.json，原型浏览器持久化，不是酒馆正式存档；临时文件写完再rename。储存失败显示提示，损坏文件保留；清除按钮是玩家主动动作。多标签单写者锁、外部宿主权威、来源身份与正式结果字段仍待接入，不能用本机记录假称关闭真实宿主门。

候选UI优先清楚的命令、资源和意图，统一深蓝背景/青绿己方/暖红敌方/米金重点。旧失败角色动画均未接入新页面。当前是页面与机制建设，正式战斗场景/镜头/素材等待新路线输入，不能把无角色场景的卡片布局声称正式美化完成。

验证目标：完整胜利/失败/撤退/再玩、半回合刷新不重复扣费、错误目标/旧指令不改变状态、支持者确实支援且无强制攻击、新旧规则各自可恢复、浏览器滚动选择不跳回顶部、无档没有假继续。自动与实际浏览器证据分记evidence/gameplay-08.md，唯一进度仍根交接单。
