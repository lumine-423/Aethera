# 我方角色动作与双形态制作规格

版本：party-actions-20261027。依据：用户本轮直接确认。本文落实原总计划的角色资产和验收工作；当前进度仍只写根目录交接单。

> **2026-10-29 现行覆盖：动态漫画式战斗。** 根总计划0.11／decisions E46优先。每形态的待机保留循环；其他动作采用静态关键姿势与特效、镜头、漫画硬切。动作表记录行为与读形，不要求连续人物运动、补中间帧或每动作固定五图。下文有关连续动画、关节轨迹和“不能瞬切”的旧措辞只作历史依据；允许有设计的硬切，但要验证人物身份、动作意图、目标/命中反馈、切换节奏和战斗规则的一致性。九类／19／133仍是动作槽覆盖，不代表动画段数或图片数。先以待机→普攻或技能→受击→待机作候选样片；尚未实际制作或验收。

## 1. 已冻结的动作范围

用户补充确认：**所有角色都有待机，每个形态独立制作。** 每个参战我方形态合计九类：原有八类加待机。辅助角色同样适用；其他角色的待机需求也已登记，制作批次按实际出场安排。敌人动画暂定，当前先做我方；原有几何练习靶继续用于规则测试，不扩大敌方制作。

| 动作ID | 动作 | 要制作的内容 | 接续与验收重点 |
|---|---|---|---|
| attack | 普攻 | 起势、出手/接触、随动、收招 | 角色确实参与发力，不能只播放特效；接触与反馈对应；返回本形态待机 |
| skill_1 | 技能1 | 角色专属关键动作与对应表现层 | 与普攻/技能2可辨；能力和持物有来源；目标/效果待规则配置确定 |
| skill_2 | 技能2 | 第二种专属动作与对应表现层 | 不能用同一普攻仅换颜色充数；允许有依据地复用局部姿势，但需独立验收 |
| ultimate | 大招 | 比普通技能更明确的蓄势、释放、高潮与收束 | 有本角色身份，节奏清楚；镜头/特效不能遮掩角色运动；剧情锁定与重大代价保留 |
| hit | 受击 | 接触反应、重心变化、缓冲/恢复 | 受击方向和力度可读；普通受击与倒地区分；是否多方向/轻重变体按确认玩法决定 |
| guard | 防御 | 进入防御、可持续姿势/循环、退出 | 肢体/护盾/武器有支撑，受击不立刻跳回站姿；三段是这一类动作内部结构，不新增三个玩法 |
| down | 倒地 | 失衡、落地/失能、稳定停留 | 不自动等同死亡；不能把空中机甲切成普通人倒地；起身/复活只有玩法需要时补 |
| settlement | 结算 | 符合角色的结算动作及稳定停留 | 不要求所有人同一种庆祝；倒地/失败者不自动起身欢呼。胜负/存活分支政策未冻结前保留为待绑定 |
| idle | 待机 | 呼吸、自然平衡、适度发尾/衣物/附属物运动，形成连续循环 | 双脚与重心合理，循环接缝无跳变；形态专属；不同动作回待机均自然，不用整张图上下漂移替代 |

**七罪角色：基础八类＋解放过渡一条＋解放形态八类，共17条用户要求的主动作。** “解放技能”在本轮按触发形态变化的动作理解，不凭空另加一条解放攻击；是否同时带伤害/增益由后续战斗规则决定。

解放形态要完整重做八类动作的造型、持物、运动和特效关系，不是基础形态套色。可以复用骨架设计、制作工具和经检查的局部运动，但源与运行资产分别登记，逐条验收。大招和解放是两个动作槽，不能互相替代。

**待机idle已由用户明确列为必做**，不是可选配套。为沿用前一轮清单，仍把原八类与待机分栏记账，但验收计算全部必需项。入场、走跑、闪避、复活、解除解放、额外剧情动作不因本表自动成为必做；如果真正采用对应流程，再补有依据的任务。

七罪合计：14套形态×9＋7条解放过渡＝**133条必需动作**，每人19条。其中原八类/过渡119条、待机14条分栏保留。这里的“条”是动作类别，不是帧数/图层数/贴图数。**当前正式完成数仍为0**；待机/攻击研究稿不抵扣已通过验收的正式动作。

## 3. 动作槽与设定技能名分开

动作槽是资产合同，技能名称是内容映射。世界书中的技能数与游戏固定槽位数不一定相等，不能按出现顺序把两个词塞进技能1/2，再拿剩余词强凑大招。

每次绑定必须写：原条目ID/指纹→原设定能力→拟映射槽位→视觉动作卡→规则效果/目标/消耗→剧情可用性→接受状态。设定明确、动作细节可逆时可以自主制作候选；技能组合、数值、解锁、不可逆代价未定时保留待确认，不阻塞通用动作和角色源的研究。

游戏适配以用户最新说明为准，具体合同见 `gameplay-adaptations.md`。以下已替代此前从旧世界书直接推导的游戏禁令：

- 凛零【飞星】已由用户定义为超加速、突破空间限制的大招，允许制作；先绑定鸟羽形态ultimate槽。旧快照的未解锁状态保留为历史来源，不再阻止游戏制作。
- 梅林【降神】已允许改编为游戏内高消耗、高伤害、高代价大招；不照搬剧情永久一次性限制，不把游戏代价反写为剧情永久封技。与艾利丝的同名能力保留角色配置边界。
- 世界书写明的小时/天冷却属于世界设定。游戏当前没有时间/冷却换算规则，不能擅自改成回合数或自动推进角色卡时间。
- 明空等无战斗技能角色已允许设计为辅助，提供增益、治疗等；叶/瓦尔基里/阿兰雅可沿辅助路线制作候选。基础attack槽可呈现为基础援护，不强行赋予伤害能力；首玩阵容与具体数值仍需后续设计。

## 4. 程序与美术共用的最小合同

机器清单 `party-animation-manifest.json` 是当前动作覆盖来源；使用稳定actor_id、form_id（base/released）、action_id定位资产，界面显示名可以变化。剧情阶段（例如焰渊其一/其二）与战斗形态不是同一字段，不能用字符串包含“变身阶段”就自动归为七罪解放。

建议目录在正式资产制作时按 `art-source/actors/{actor_id}/{form_id}/` 与 `assets/actors/{actor_id}/{form_id}/` 对应；解放过渡单独 `transitions/base_to_released`。当前草稿rin-study保留原路径和draft标记，不伪装迁移成完成的正式attack。

每条动作的可编辑源/运行图集/元数据应关联以下信息：帧序与不等时长、画布、root/接地锚点、武器/效果挂点、循环或单次、接续状态、显示倍率、视觉事件点、来源与验收证据。guard/down/settlement可包含enter/hold/exit片段，仍按同一类动作验收。效果、浮游物、召唤物可分层；独立动画层必须与主体一起测试，不能因角色八类已画而漏记机兵/巨狼等配套工作。

**解放的逻辑形态与播放时间分离：**

1. 规则接受解放命令时，校验可用形态、剧情解锁与成本并仅提交一次；逻辑结果明确from/to与action_instance_id。
2. 表现层从基础造型播放过渡，再切入released素材与待机；表现事件不能再次扣成本或提交变身。
3. 跳过直接展示已提交目标形态；暂停停住同一演出时钟；旧回调按action_instance_id丢弃。
4. 重载从持久逻辑form_id和动作记录恢复稳定状态；不从“第几帧”猜是否已变身，也不重扣成本。内容版本改变按明确迁移政策处理。
5. 倒地与结算优先使用当前逻辑形态对应资产；解除解放、战后是否回基础、冷却写回等尚未定，不以动画结束自动改变正式角色状态。

这是下一段引擎实现合同，**当前technical-fixture-01还没有解放指令或form_id持久化**；不要把本文件当运行已实现。修改正式检查点前递增内容/存档版本并保留旧夹具证据，不能直接把新动作塞进旧版本重放序列。

## 5. 制作顺序与验收

1. 先完成凛零基础动作的统一比例/身份、待机与普攻样板，修现有失败项，不扩散六姿势稿的问题。
2. 同一角色闭合八类动作＋待机，逐条过自然动作门；技能映射未定时先做受击、防御、倒地与候选分镜，不能用空资产宣称完成。
3. 为鸟羽做独立轮廓/姿态样板、解放过渡和第二套八类＋待机，验证整个双形态状态链。
4. 一名七罪双形态样板通过后，再按同一合同扩另外六人；每人武器/附属物不同，必须做专属动作卡，不批量套模板假装角色差异。
5. 其他我方成员确认后自动应用基础八类＋待机；当前10名来源角色只是核查清单，不全部默认进首玩阵容。敌人保持暂定。

每个形态实际操作验收：idle→attack/skill_1/skill_2/ultimate→本形态idle；guard进入/受击/退出；hit恢复；down稳定；settlement分支；base→liberate→released重复以上八类。再测演出中暂停/跳过/失焦/重载/重复回调，确认状态和一次提交一致。测试期间可用开发目标触发我方受击，不需要先建完整敌方动画库。

发布拒收：少一个必需槽、released偷用base服装/轮廓、只做变身没有第二套八类、锁定技能被启用、跳过或重载改变形态成本、倒地者无故庆祝、结构通过却运动僵硬。沿用 `art-direction-and-acceptance.md` 的三层门；脚底指标与自动检查不代替自然动作和用户接受。

检查命令：`python tools/check_party_animation_manifest.py` 只检查覆盖与来源完整，报告未完成数；**通过此检查不等于119条动画已制作**。
