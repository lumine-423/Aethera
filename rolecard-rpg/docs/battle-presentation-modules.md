# 战斗演出模块与素材制作约定

2026-10-29 用户确认：以生图为复杂特效素材的中心；简单粒子等普通基础特效允许由 Godot 制作。只要特效稍复杂，就用生图制作，需要多少帧就生成多少张对应图；不以程序变形/插值冒充已生成的独立特效帧。数量、效果和调用额度按实际动作计划及生成结果记录，不能保证独立生图天然连续一致。当前仅凛零待机样片已制作，特效模块均为设计清单，未生成也未在战斗实测。

**资源优先级（2026-10-29 用户明确）**：本路线重点是演出与特效，应充分倾斜制作资源，准备充足的可复用通用资源及角色／技能专属资产，不以减少人物连续动画为由简化表现；实际规模和通过标准按样片及后续技能设计验证。首个凛零普攻样片见 `../art-source/rin-attack-mad-01/README.md`；这不是完整特效库。

**2026-10-29 分类与帧数新增要求**：通用屏幕速度线必须中性、可跨角色；贴在角色身上的动作轨迹为角色/形态/动作专属。每个动态特效层先确定时长，再按至少24张独立生图/秒制作，向上取整；不同图连续性、透明边缘和实际播放需单独审查。具体工作流和可复制配置见 `../art-source/battle-presentation-template/工作流与模板.md`。凛零样片现有24fps各自独立的屏幕速度线、动作轨迹和空间裂痕，但仍为待审候选，独立帧之间存在变化风险，不是素材库正式验收。

**2026-10-29 用户修订：** 受击命中光效为一张通用静态图，环绕受击者、中间留空，受击者与其光效局部抖动；不是24帧动态图，也不触发屏幕闪/震。效果须读得出冲击，不能像纯UI刻度。普攻暂不使用通用速度线，后续重做；旧凛零空间特效过繁待返工。特效以简洁、几何为基调，同时保留行为可读性。其他明确采用的动态特效仍遵守24张独立画面/秒。当前新环与受击/昏迷/胜利仅候选，未接受。

## 模块及边界

| 模块 | 使用范围与输入 | 制作与验收 |
|---|---|---|
| 待机角色 | 角色ID、形态、透明素材、锚点、动作开关 | 本次凛零用参考图比例的非像素生图；单图轻微呼吸式变形只是样片，不是逐帧人物动画，也无独立发丝、眨眼。多形态各自管理，不借用基础造型。 |
| 通用基础特效 | 通用ID、颜色/尺寸/方向、持续时间、锚点 | 只有简单粒子或基本几何效果可由Godot程序绘制；复杂样式以生成的独立素材/帧为准，不默认为全员换色。 |
| 角色/技能专属特效 | actor/form/action、能力依据、来源图、轨迹、目标与视觉事件 | 稍复杂即生图，所需各帧逐张生成并登记原调用、参考、顺序、时间与透明边界；原设定与改编分开，检查风格一致、角色辨识及目标反馈。 |
| 黑白闪 | 事件触发、持续时间、影响层、闪烁强度 | 基础全屏或局部颜色切换可由Godot完成；若需要复杂纹理、图案或造型则生图。默认避免遮挡重要信息，并可减弱或关闭。未实现。 |
| 速度线 | 方向、中心、层次、颜色、持续时间 | 简单直线可程序绘制；精细纹理、复杂分层或特殊造型按需求逐帧生图。相机/画面移动不应误导目标方向。未实现。 |
| 裂框特写 | 特写图、原创裂框素材、遮罩、文字、分镜顺序 | 角色特写及复杂裂框以生图制图，按需要生成各帧；Godot负责层级、遮罩、切换/位置/时序。标志性表现参考节奏，不复用受限素材。未实现。 |
| 镜头与剪辑 | 动作ID、位置/持续、遮挡/目标和恢复 | Godot负责镜头变化、硬切、分镜排列、轻震与命中停顿；过渡和目标读形由实机与用户评审。未实现。 |
| 调度与规则 | 一次已提交的行动、演出事件、视觉/音频完成或跳过 | 表现不负责伤害重复结算；暂停/跳过/失焦/恢复要与规则保持一致。当前仅规格，未实现。 |

## 素材登记建议

独立保留原始生成图和运行资产；每项记录通用或专属、角色/形态/动作、输入图与指纹、原始调用提示词、帧顺序与时长、透明和画布/锚点、配色/目标、来源许可、版本及用户审阅状态。相互独立的角色、特效、分镜、音效图层可更换，不把特效直接烘入角色图。能否复用由视觉验证决定，不等于仅改色即可用于所有角色。
