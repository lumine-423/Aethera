当前已确认：游戏依附角色卡，沿用艾瑟拉来源；当前不承担故事/对话/探索。战斗由游戏板块主动触发，或由剧情指令唤起指定任务。当前技术样片仅用 `probe.basic` 验证链路；数值、几何靶/背景与凛零关键姿势草稿均不是正式内容。

## 职责与状态所有者

| 位置 | 当前责任 | 不应承担 |
|---|---|---|
| 角色卡宿主适配器 | 识别正确角色卡/会话/消息候选，形成请求，加载游戏板块，持久化与去重结果，向后续剧情提供经过校验的结果 | 把模型给出的任意脚本或数值直接传入游戏执行 |
| Godot 游戏 | 校验任务请求，运行一套战斗规则和像素表现，返回明确结果 | 自己编写故事、主动调用模型、直接持有酒馆凭据或替换整份 stat_data |
| 原有 MVU/卡片状态 | 维持既有角色与剧情状态，按核验后的最小边界接纳游戏结果 | 因新增游戏模块而被整表覆盖或被局内动画重复修改 |
| 本地 harness | 模拟两个入口、观察请求/结果与去重 | 充当正式存档、证明真实卡片接入已通过 |

建议采用长生命周期的单一游戏实例，位于游戏板块/专用弹层。剧情消息的重绘不应重新创建战斗。实际挂载位置在确认当前覆盖层与普通版的有效源后再冻结，不能运行旧打包器覆盖漂移的活卡。

## 当前已实现的局部协议

请求字段：`protocol_version=1`、稳定 `request_id`、白名单 `task_id`、`source=manual|story`。协议拒绝额外字段，不接受外部生命、奖励、敌方配置或脚本。相同请求 ID、相同内容不得重置战斗；同 ID 不同内容拒绝；活动战斗期间其他请求明确拒绝忙碌，不隐式覆盖。

结果字段：`request_id`、`result_id`、`task_id`、`source`、`content_version`、`outcome`、必要战斗摘要。技术结果只有 victory/defeat/cancelled；正式失败与取消规则仍需依游戏设计确定。宿主必须先匹配登记请求，再提交一次；重复结果只回执，不再次发奖或推进剧情。

开发传输：`postMessage` 只接受确切 parent/source、允许 origin、版本、通道与本次实例 token；消息有大小和队列上限。当前只允许 8765 本地验证来源，**尚未加入 SillyTavern 来源，也未部署到真实卡片**。token 只是实例关联，不宣称防范同源恶意脚本。

剧情候选格式：在已完成的角色消息原文中，独占一行的 `<RpgBattle>{"task_id":"...","event_key":"..."}</RpgBattle>`。这是项目新协议提案，不是 SillyTavern 原生语法。解析器已经拒绝用户消息、未完成输出、引用行、代码围栏、多个指令、未知任务与额外字段。正式宿主还必须核验当前消息/候选、流式完成和会话身份，再决定何时自动唤起。

## 第二轮已实现的状态与恢复

`web/host-coordinator.mjs` 把任务登记、检查点、剧情绑定、结果提交从页面按钮逻辑中抽出。它接收明确的 `{card_id,chat_id,branch_id}`；一个实例只属于一个上下文。身份必须由真实宿主提供，本模块不猜真实 swipe 谱系。harness 下拉 A/B 是人工测试身份，不能推论实际酒馆回滚已通。

持久文档为 schema_version=1、revision、active_id、requests、story_bindings、results。当前每上下文最多128请求，到上限明确拒绝，不静默删除完成记录造成重复触发。剧情绑定包含 message_id、swipe_id、内容指纹、event_key；同绑定已结束时返回原结果。未来清理/归档和重新挑战政策应单独决定，不能把保留去重变成静默丢进度。

引擎输出局内检查点，只包含内容版本、原请求、已提交指令序列与取消标记。**不从宿主快照直接接受生命/伤害/奖励**。Godot 在临时 session 中用同一套规则重放合法动作，再替换当前状态；重放失败不破坏原状态。换内容版本拒绝恢复，不猜迁移。宿主要求检查点单调增加且保持既有前缀，结果先绑定已登记请求、版本、结果字段及行动数/取消终态，再持久提交。宿主不独立重算全部战斗数值，这不是服务端防作弊方案。

完成和去重以持久写入成功为界。写失败保留原活动请求，供重试/重载重建；不先报告已提交再丢结果。读取时检查版本、请求/结果/活动项/剧情绑定之间的引用；损坏数据明确报错并保留，不能自动清空成新游戏。

| 存储实现 | 当前状态 | 限制 |
|---|---|---|
| createLocalProbeStore | 浏览器localStorage，实际整页刷新/重载/测试分支已测 | 只属于开发站点，清浏览器数据会丢；不是角色卡正式存档，不声称跨标签原子事务 |
| createTavernStore | 依赖注入源码候选，针对当前已核实的同步 getVariables/updateVariablesWith；自动测试不覆盖无关stat_data | 尚未安装/调用真实卡。提案仅拥有chat变量中的sigil_rpg_v1；真实namespace、身份、回退与写入事件仍需宿主验证 |

Tavern候选在同步updater内复查上下文和revision，合并自己命名空间，保留其他变量。当前安装源码允许同步updater返回同步结果，但它最终仍是整份变量副本replace，**不具备与别的脚本/标签之间的事务隔离**。实际接入采用一个宿主协调器串行写，发生revision冲突时重新读取并让用户看见可重试状态；不能无条件覆盖。

本轮真实浏览器证据见 `evidence/probe-02.md`；真实卡片/下一轮剧情可见性/正式MVU字段仍单独过门。

## 下一段必须关闭的实际宿主检查点

1. 找到当前活卡与覆盖层/普通版有效入口；只读记录身份和指纹，保护原有脚本与桥。
2. 在正确脚本上下文读取能力、会话身份、当前消息/候选，确认取到完整输出的可靠事件；不在流式 token 或每次重绘时直接开战。
3. 冻结请求记录的持久作用域和分支政策。剧情任务绑定具体消息候选；切会话、swipe、重生成、编辑/删除后的行为明确，不能靠本地 Map 宣称持久去重。
4. 只交换任务与必要局内快照，不把整段私密聊天、扩展设置或凭据发给游戏 iframe。
5. 先在测试对话/测试模块中走双入口与结果回执，再扩展实际角色状态的写入；读取、提交、下一轮剧情可见分别验证。
6. 两类入口在取消、失败、重复唤起、切卡、刷新、关闭游戏板块后均有确定行为。尚未定义的正式奖励与生命代价不能随技术夹具写入原卡。

本合同是现有总计划对应接入任务的接口说明，不是新增平行蓝图或进度入口。当前进度仍只写根目录的角色卡RPG开发交接单。
